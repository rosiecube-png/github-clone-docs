# ADR-0003: CI 작업 격리에 컨테이너 런타임을 필수 의존성으로 둔다

- **상태**: 채택됨
- **일자**: 2026-08-07
- **해소한 질문**: Q-03
- **관련**: [ADR-0001](0001-implementation-language-rust.md), NFR-SEC-01, NFR-OPS-03, CON-09

## 맥락

워크플로는 임의의 사용자 코드를 실행한다. 격리 실패는 곧 서버 장악이다.
동시에 헌장은 외부 의존성을 두지 않는 것을 제약으로 삼는다(CON-02).
자체 격리를 구현하면 의존성은 없지만 난이도와 보안 위험이 크고,
플러그형으로 만들면 구성 요소와 시험 매트릭스가 늘어 CON-09·NFR-OPS-07과 충돌한다.

## 결정

**컨테이너 런타임을 CI 실행의 필수 의존성으로 둔다.**

이것은 NFR-OPS-03(외부 관리형 서비스 비의존)의 **명시적 예외**다.
컨테이너 런타임은 관리형 클라우드 서비스가 아니라 고객 인프라에 설치되는
소프트웨어이므로 데이터 주권과 에어갭 제약을 해치지 않는다. 다만
「구성 요소를 늘리지 않는다」는 원칙은 어기므로, 그 값어치를 여기 기록한다.

- 임의 코드 실행의 격리는 우리가 직접 구현하기에 위험이 너무 크다.
- 상류 워크플로 생태계가 이미 컨테이너를 전제한다. 호환(CON-08)을
  우선하기로 한 이상 이 전제를 피할 수 없다.
- 액션의 저장·반입 형식을 컨테이너 이미지로 통일할 수 있게 되어
  NFR-OPS-08(반입 절차 단일화)이 실현 가능해진다.

## 파생 제약

`CON-12`로 등록한다. **CI 기능을 켠 인스턴스는 컨테이너 런타임을 요구한다.**

- CI를 끈 구성에서는 이 의존성이 없어야 한다(NFR-LIGHT-05).
  플랫폼 코어만 쓰는 조직에 런타임을 강요하지 않는다.
- 러너는 보장 등급 두 아키텍처에서 모두 동작해야 한다(NFR-PORT-01).
- **확인된 상류 제약**: 컨테이너 기반 액션은 리눅스 러너에서만 실행된다.
  이 한계를 우리가 없앨 수 없으므로 문서에 명시한다.

## 결과

**긍정** — 격리 구현 위험을 피한다. 상류 워크플로가 그대로 동작할 여지가 커진다.
액션 반입이 이미지 하나의 문제로 단순해진다.

**부정 / 감수하는 것** — 필수 의존성이 하나 늘었다. 관리자가 런타임을 설치·유지해야
하고, 그 자체의 취약점이 우리 공격 표면이 된다. 아키텍처별 이미지 문제가
NFR-PORT와 얽힌다.

## 상태가 바뀐 요구사항

`보류` → `초안`: NFR-SEC-01, FR-CI-12, FR-CI-17

## 미결

- 특정 런타임 구현을 고정할 것인가, 인터페이스만 정하고 여럿을 허용할 것인가
- 컨테이너 밖 추가 격리(사용자 네임스페이스, 자원 제한, 네트워크 정책)의 수준
