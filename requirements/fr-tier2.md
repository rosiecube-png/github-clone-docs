# 기능 요구사항 — Tier 2

작성 규칙과 상태 정의는 [README](README.md)를 따른다. Tier 1은 [fr.md](fr.md).

Tier 2는 "팀이 실제로 쓰려면 필요하다"에 해당한다. 이 계층이 완성되어야
헌장의 성공 기준 5(dogfooding)와 2(대체 가능성)가 성립한다.

---

## 워크플로·CI — FR-CI

이 도메인은 **NFR-COMPAT-05(에어갭에서의 워크플로 호환)와 NFR-SEC-01(작업 격리)이
해소되기 전까지 상당수가 `보류`다.** 문법만 맞추고 넘어가면 폐쇄망에서
동작하지 않는 기능이 된다.

### FR-CI-01 — 워크플로 정의 인식
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002 (워크플로 문법 L1)
- **서술**: 저장소의 약속된 경로에 있는 워크플로 정의 파일을 인식해 해석한다.
  GitHub Actions의 워크플로 문법을 따른다.
- **수용 기준**: 실제 공개 프로젝트의 워크플로 파일을 수정 없이 해석해
  job·step 구조를 정확히 산출한다.

### FR-CI-02 — 이벤트 트리거
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002
- **서술**: push, PR 생성·갱신, 태그, 일정, 수동 실행, 다른 워크플로 완료 등의
  이벤트로 워크플로를 기동한다. 브랜치·경로 필터를 지원한다.
- **수용 기준**: 각 트리거와 필터 조합에 대해 기동 여부가 기대와 일치.

### FR-CI-03 — job 실행과 의존 관계
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002
- **서술**: job 간 의존 관계를 해석해 순서와 병렬성을 결정하고, 조건식에 따라
  job·step을 건너뛴다. 선행 job의 출력을 후행 job이 받을 수 있다.
- **수용 기준**: 의존 그래프·조건·출력 전달에 대한 시험 모음이 통과.

### FR-CI-04 — 매트릭스 전개
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002
- **서술**: 매트릭스 정의를 전개해 조합별 job을 생성하고, 포함·제외 규칙과
  실패 시 중단 정책을 지원한다.
- **수용 기준**: 전개 결과 조합 수와 각 조합의 변수 값이 기대와 일치.

### FR-CI-05 — 재사용 액션 참조 해석
- **상태**: **보류** (해소안 미결) · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002 충돌 1, NFR-COMPAT-05, NFR-OPS-01
- **서술**: 워크플로가 참조하는 외부 재사용 액션을 **인스턴스 내부에서** 해석해
  실행한다. 런타임에 외부 네트워크로 나가지 않는 것이 기본값이다.
- **수용 기준**: 아웃바운드가 차단된 인스턴스에서 외부 액션을 참조하는
  실제 워크플로가 성공한다. **문법 파싱 성공은 통과가 아니다.**
- **비고**: 이 요구사항이 CI 도메인 전체의 성패를 가른다. 미러링 방식,
  반입 절차, 대상 액션의 재배포 라이선스가 모두 선행 결정이다.
  [open-questions.md](open-questions.md) Q-01.

### FR-CI-06 — 시크릿 주입
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: NFR-SEC-02
- **서술**: 저장소·조직·환경 수준의 시크릿을 실행 환경에 주입한다.
  신뢰할 수 없는 출처(포크에서 온 PR)의 실행에는 주입하지 않는다.
- **수용 기준**: 포크 PR 시나리오에서 미주입을 확인. 로그 전체에서 시크릿 값이
  검출되지 않음을 자동 확인.

### FR-CI-07 — 로그 스트리밍
- **상태**: 초안 · **Tier**: T2 · **호환**: L2
- **출처**: 헌장 범위 T2
- **서술**: 실행 중인 job의 출력을 실시간으로 조회할 수 있고, 완료 후에는
  보존 정책이 허용하는 기간 동안 다시 볼 수 있다.
- **수용 기준**: 실행 중 조회에서 지연이 사람이 인지하는 수준을 넘지 않고,
  연결이 끊겼다 재개해도 누락이 없다.

### FR-CI-08 — 아티팩트와 캐시
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: 헌장 범위 T2, NFR-OPS-06
- **서술**: job이 산출물을 업로드·다운로드하고, 의존성 캐시를 저장·복원한다.
  둘 다 보존 정책과 용량 상한을 따른다.
- **수용 기준**: 기존 워크플로의 업로드·다운로드·캐시 단계가 수정 없이 동작하고,
  상한 초과 시 회수가 동작한다.

### FR-CI-09 — 취소와 타임아웃
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: 헌장 범위 T2
- **서술**: 실행 중인 워크플로를 취소할 수 있고, job별 타임아웃이 적용된다.
  취소·타임아웃 시 실행 중이던 프로세스와 자원이 회수된다.
- **수용 기준**: 취소 후 자원 점유가 남지 않음을 확인.

### FR-CI-10 — 동시성 제어
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: 헌장 범위 T2
- **서술**: 동시성 그룹을 지정해 같은 그룹의 이전 실행을 대기시키거나 취소한다.
- **수용 기준**: 그룹 정의에 따른 대기·취소 동작이 기대와 일치.

### FR-CI-11 — 실행 상태의 PR 반영
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: FR-PROT-04의 선행 요구
- **서술**: 워크플로 실행 결과를 커밋·PR의 상태로 보고하며,
  이 상태를 머지 조건으로 쓸 수 있다.
- **수용 기준**: 공식 API 클라이언트가 상태를 조회할 수 있고,
  FR-PROT-04의 필수 체크로 동작한다.

### FR-CI-12 — 러너 등록과 배정
- **상태**: **보류** (격리 방식 미결) · **Tier**: T2 · **호환**: L3
- **출처**: NFR-SEC-01, NFR-PORT-01
- **서술**: 관리자가 러너를 등록하고 레이블로 job을 배정한다.
  러너는 보장 등급 아키텍처 모두에서 동작한다.
- **수용 기준**: x86_64·aarch64 러너 각각에서 job이 실행되고,
  레이블 기반 배정이 기대와 일치.
- **비고**: 격리 방식이 아키텍처별 실행 이미지 문제를 낳는다.
  [open-questions.md](open-questions.md) Q-03.

## 웹훅·알림 — FR-HOOK

### FR-HOOK-01 — 웹훅 등록
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: 헌장 범위 T2
- **서술**: 저장소·조직 수준에서 대상 URL과 구독 이벤트를 지정해 웹훅을
  등록·수정·삭제한다.
- **수용 기준**: 공식 API 클라이언트로 등록·조회가 성공.

### FR-HOOK-02 — 페이로드 호환
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002 (웹훅 페이로드 L1)
- **서술**: 이벤트 페이로드의 구조와 이벤트 종류 이름이 GitHub과 호환되어,
  기존 수신 측 구현이 수정 없이 해석한다.
- **수용 기준**: 기존 웹훅 수신 라이브러리·봇이 페이로드를 정상 해석.

### FR-HOOK-03 — 서명
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002
- **서술**: 공유 시크릿 기반 서명 헤더를 붙여 수신 측이 진위를 검증할 수 있게 한다.
- **수용 기준**: 기존 검증 구현이 서명을 통과시킨다. 변조된 페이로드는 거부된다.

### FR-HOOK-04 — 전달 보장과 재시도
- **상태**: 초안 · **Tier**: T2 · **호환**: L3
- **출처**: 헌장 저장소 구성(webhooks)
- **서술**: 최소 1회 전달을 목표로 하고, 실패 시 지수 백오프로 재시도한다.
  이벤트마다 고유 식별자를 부여해 수신 측이 중복을 제거할 수 있게 한다.
- **수용 기준**: 수신 측 장애를 주입한 뒤 복구했을 때 이벤트가 전달되고,
  중복 전달 시 식별자가 동일하다.

### FR-HOOK-05 — 전달 이력과 재전송
- **상태**: 초안 · **Tier**: T2 · **호환**: L2
- **출처**: 운영 요구
- **서술**: 최근 전달 시도의 요청·응답과 결과를 조회하고 수동 재전송한다.
  반복 실패한 웹훅은 자동으로 비활성화하고 소유자에게 알린다.
- **수용 기준**: 이력 조회와 재전송이 동작하고, 임계 초과 시 비활성화된다.

### FR-HOOK-06 — 대상 주소 제한
- **상태**: 초안 · **Tier**: T2 · **호환**: L3
- **출처**: NFR-SEC-03
- **서술**: 내부망·루프백·링크로컬 주소로의 전달을 차단하며, 리다이렉트를 통한
  우회도 차단한다. 관리자가 허용 목록으로 예외를 둘 수 있다.
- **수용 기준**: 우회 시도 모음이 모두 차단됨을 확인.

### FR-HOOK-07 — 인앱 알림
- **상태**: 초안 · **Tier**: T2 · **호환**: L2
- **출처**: 헌장 범위 T2
- **서술**: 멘션, 리뷰 요청, 담당자 지정, 구독 중인 스레드의 활동을
  사용자별 알림으로 만들고 읽음 처리한다.
- **수용 기준**: 알림 생성 조건별 시험이 통과하고 읽음 상태가 유지된다.

### FR-HOOK-08 — 이메일 알림
- **상태**: 초안 · **Tier**: T2 · **호환**: L3
- **출처**: NFR-OPS-03
- **서술**: 관리자가 지정한 메일 서버로 알림을 발송한다.
  메일 서버 미설정 시에도 제품의 나머지 기능은 완전히 동작한다.
- **수용 기준**: 메일 설정을 비운 구성에서 전체 수용 시험 통과.

### FR-HOOK-09 — 구독 설정
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: 헌장 범위 T2
- **서술**: 저장소·스레드 단위로 알림 구독 수준을 설정한다.
- **수용 기준**: 구독 수준별로 알림 발생 여부가 기대와 일치.

## 검색 — FR-SEARCH

### FR-SEARCH-01 — 저장소 검색
- **상태**: 초안 · **Tier**: T2 · **호환**: L2
- **출처**: 헌장 범위 T2
- **서술**: 이름·설명·토픽으로 저장소를 검색한다.
- **수용 기준**: 검색 결과가 요청자의 권한 범위 내로 제한된다.

### FR-SEARCH-02 — 이슈·PR 검색
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: ADR-0002
- **서술**: 상태·라벨·담당자·작성자·기간 등을 조합한 검색을 지원하며,
  쿼리 문법이 GitHub과 호환된다.
- **수용 기준**: 기존 도구가 생성하는 검색 쿼리가 수정 없이 해석된다.

### FR-SEARCH-03 — 코드 검색
- **상태**: 초안 · **Tier**: T2 · **호환**: L2
- **출처**: 헌장 범위 T2
- **서술**: 저장소 내용에서 문자열을 검색하고, 언어·경로로 좁힌다.
- **수용 기준**: 기준 데이터셋에서 정확도와 응답 시간을 측정해 공개.

### FR-SEARCH-04 — 권한 반영
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: NFR-SEC-05, FR-REPO-02
- **서술**: 검색 결과에 요청자가 접근할 수 없는 자원이 포함되지 않으며,
  결과 건수로도 존재가 유추되지 않는다.
- **수용 기준**: 권한 조합별 검색 결과 전수 시험 통과.

### FR-SEARCH-05 — 색인 갱신
- **상태**: 초안 · **Tier**: T2 · **호환**: L3
- **출처**: 헌장 범위 T2
- **서술**: 변경이 색인에 반영되기까지의 지연에 상한이 있고, 그 값을 공개한다.
  색인 재구축을 관리자가 수행할 수 있다.
- **수용 기준**: 변경 후 반영 시간을 측정해 공개된 상한 내임을 확인.

### FR-SEARCH-06 — 색인 자원 상한
- **상태**: 초안 · **Tier**: T2 · **호환**: L3
- **출처**: NFR-OPS-06, NFR-LIGHT-05
- **서술**: 색인의 디스크·메모리 사용에 상한을 두며, 검색을 끈 인스턴스에서는
  색인 자원을 점유하지 않는다.
- **수용 기준**: 검색 비활성 구성에서 색인 자원 점유가 0임을 확인.

## 보호 규칙 — FR-PROT

### FR-PROT-01 — 브랜치 보호 규칙 정의
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: 헌장 범위 T2, FR-GIT-06
- **서술**: 브랜치 이름 패턴에 대해 보호 규칙을 정의한다.
  여러 규칙이 겹칠 때의 우선순위가 정의되어 있다.
- **수용 기준**: 공식 API 클라이언트로 규칙을 설정·조회할 수 있고,
  겹치는 규칙의 적용 결과가 문서와 일치.

### FR-PROT-02 — 강제 푸시·삭제 차단
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: FR-GIT-06
- **서술**: 보호된 브랜치에 대한 강제 푸시와 삭제를 차단하고 사유를 전달한다.
- **수용 기준**: 표준 git 클라이언트의 출력에 거부 사유가 표시된다.

### FR-PROT-03 — 필수 리뷰
- **상태**: 초안 · **Tier**: T2 · **호환**: L1
- **출처**: 헌장 범위 T2
- **서술**: 머지 전 필요한 승인 수를 요구하고, 새 커밋이 푸시되면 기존 승인을
  무효화하는 정책을 선택할 수 있다.
- **수용 기준**: 승인 수 미달 시 머지가 차단되고, 무효화 정책이 동작한다.
