# 기능 요구사항 (FR)

작성 규칙과 상태 정의는 [README](README.md)를 따른다.

이 문서는 **Tier 1**을 담는다.
Tier 2는 [fr-tier2.md](fr-tier2.md), Tier 3은 [fr-tier3.md](fr-tier3.md)에 있다.

호환 등급이 `L1`인 요구사항의 수용 기준은 **기존 GitHub 클라이언트로 판정한다**
(NFR-COMPAT-02). 우리가 만든 클라이언트로 통과시킨 것은 통과가 아니다.

## 계정·인증 — FR-AUTH

### FR-AUTH-01 — 계정 생성
- **상태**: 초안 · **Tier**: T1 · **호환**: L3
- **출처**: 헌장 범위 T1
- **서술**: 관리자가 계정을 생성하거나, 관리자가 허용한 경우 사용자가 스스로
  가입할 수 있다. 가입 개방 여부는 인스턴스 설정이다.
- **수용 기준**: 두 경로 모두로 계정이 생성되고, 가입을 닫은 인스턴스에서
  자가 가입이 거부된다.

### FR-AUTH-02 — 세션 인증
- **상태**: 초안 · **Tier**: T1 · **호환**: L3
- **출처**: 헌장 범위 T1
- **서술**: 웹 UI에서 자격 증명으로 로그인하고 세션을 유지·종료할 수 있다.
- **수용 기준**: 로그인·로그아웃·세션 만료가 동작하고, 만료된 세션으로
  보호된 자원에 접근할 수 없다.

### FR-AUTH-03 — 개인 액세스 토큰
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1, ADR-0002
- **서술**: 사용자가 범위(scope)와 만료를 지정한 토큰을 발급·폐기할 수 있으며,
  이 토큰으로 API와 git 프로토콜에 인증한다.
- **수용 기준**: 발급한 토큰으로 공식 CLI와 표준 git 클라이언트가 인증에 성공한다.
  폐기 후에는 즉시 거부된다. 범위를 벗어난 요청이 거부된다.
- **비고**: 토큰은 발급 시점에만 평문으로 보이고, 이후 저장소에서 복원 불가해야 한다.

### FR-AUTH-04 — SSH 공개키 등록
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1 (git 프로토콜)
- **서술**: 사용자가 SSH 공개키를 등록·삭제하고, 그 키로 git 작업을 인증한다.
- **수용 기준**: 등록한 키로 표준 git 클라이언트의 SSH clone/push가 성공하고,
  삭제 후 거부된다.

### FR-AUTH-05 — 토큰·키의 사용 이력
- **상태**: 초안 · **Tier**: T1 · **호환**: L3
- **출처**: NFR-SEC-06
- **서술**: 각 토큰과 공개키의 마지막 사용 시각을 기록해 사용자에게 보여준다.
- **수용 기준**: 사용 후 해당 값이 갱신됨을 확인.

## 조직·팀·권한 — FR-ORG

### FR-ORG-01 — 조직
- **상태**: 초안 · **Tier**: T1 · **호환**: L2
- **출처**: 헌장 범위 T1
- **서술**: 조직을 생성하고 멤버를 추가·제거할 수 있다. 조직은 저장소를 소유한다.
- **수용 기준**: 조직 소유 저장소가 생성되고, 멤버십 변경이 접근 권한에 반영된다.

### FR-ORG-02 — 팀
- **상태**: 초안 · **Tier**: T1 · **호환**: L2
- **출처**: 헌장 범위 T1
- **서술**: 조직 내 팀을 만들고, 팀 단위로 저장소 접근 권한을 부여한다.
- **수용 기준**: 팀에 부여한 권한이 소속 멤버 전원에게 적용되고,
  팀에서 제외되면 회수된다.

### FR-ORG-03 — 역할 기반 권한
- **상태**: 초안 · **Tier**: T1 · **호환**: L2
- **출처**: 헌장 범위 T1, NFR-SEC-05
- **서술**: 저장소에 대한 접근을 역할로 표현한다. 역할 이름과 각 역할이 허용하는
  작업의 범위는 GitHub의 개념을 따른다.
- **수용 기준**: 역할별 허용·거부 작업 전수 시험이 존재하고 통과한다.

### FR-ORG-04 — 권한 판정의 단일 경로
- **상태**: 초안 · **Tier**: T1 · **호환**: L3
- **출처**: NFR-SEC-05
- **서술**: 저장소 공개 범위, 직접 협업자, 팀 권한, 조직 역할이 겹칠 때의
  판정 규칙을 한 곳에서 정의하고, 웹·API·git 서버가 모두 이를 경유한다.
- **수용 기준**: 세 접근 경로가 동일한 권한 조합에 대해 동일한 결과를 낸다.

## 저장소 — FR-REPO

### FR-REPO-01 — 저장소 생성·삭제
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 사용자 또는 조직 소유로 저장소를 생성하고, 이름 변경·삭제할 수 있다.
- **수용 기준**: 공식 CLI와 공식 API 클라이언트로 생성·조회·삭제가 성공한다.

### FR-REPO-02 — 공개 범위
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 저장소를 공개 또는 비공개로 설정하고 전환할 수 있다.
  비공개 저장소는 권한 없는 주체에게 존재 자체가 드러나지 않는다.
- **수용 기준**: 비인증 요청이 비공개 저장소에 대해 "권한 없음"이 아니라
  "없음"에 해당하는 응답을 받는다. 존재 여부가 유출되지 않는다.

### FR-REPO-03 — 협업자
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 저장소에 개별 사용자를 역할과 함께 협업자로 추가·제거한다.
- **수용 기준**: 추가 즉시 해당 역할의 권한이 적용되고, 제거 즉시 회수된다.

### FR-REPO-04 — 기본 브랜치
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 저장소의 기본 브랜치를 지정·변경할 수 있다.
- **수용 기준**: 변경 후 clone 시 해당 브랜치가 체크아웃된다.

### FR-REPO-05 — 저장소 메타데이터
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: ADR-0002
- **서술**: 설명, 홈페이지, 토픽, 아카이브 상태를 설정하고 API로 조회할 수 있다.
- **수용 기준**: 공식 API 클라이언트가 반환 구조를 해석할 수 있다.

## git 프로토콜 — FR-GIT

이 도메인 전체가 `L1`이다. 여기서의 비호환은 제품이 성립하지 않음을 뜻한다.

### FR-GIT-01 — Smart HTTP 전송
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1, 단계 1
- **서술**: HTTP(S)를 통한 clone / fetch / push를 지원한다.
- **수용 기준**: 표준 `git` 클라이언트로 왕복 성공. 별도 설정이나 확장 없이 동작.

### FR-GIT-02 — SSH 전송
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: SSH를 통한 clone / fetch / push를 지원하며 공개키로 인증한다.
- **수용 기준**: 표준 `git` 클라이언트로 왕복 성공.

### FR-GIT-03 — 전송 계층 권한 판정
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: NFR-SEC-05, FR-ORG-04
- **서술**: git 작업 시 요청자를 식별하고 해당 저장소에 대한 읽기/쓰기 권한을
  판정한다. 읽기 권한이 없으면 저장소 존재를 노출하지 않는다.
- **수용 기준**: 권한 조합별로 clone·push의 성공·실패가 기대와 일치.

### FR-GIT-04 — 얕은 클론과 부분 클론
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1, NFR-PERF-01
- **서술**: 깊이 제한 클론과 필터를 이용한 부분 클론을 지원한다.
- **수용 기준**: 표준 클라이언트의 해당 옵션으로 clone이 성공하고,
  이후 이력 확장(fetch)이 정상 동작한다.

### FR-GIT-05 — ref 갱신의 원자성
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: NFR-DURA-01
- **서술**: push의 ref 갱신은 전부 반영되거나 전부 반영되지 않는다.
  성공을 응답하기 전에 영속화한다.
- **수용 기준**: 다중 ref push 중 실패를 주입해 부분 반영이 없음을 확인.

### FR-GIT-06 — push 수신 시 정책 검사
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T2(보호 브랜치)의 선행 요구
- **서술**: ref 갱신을 확정하기 전에 정책(강제 푸시 허용 여부, 객체 크기 상한 등)을
  검사하고, 거부 시 사유를 클라이언트에 전달한다.
- **수용 기준**: 거부 사유가 표준 클라이언트의 출력에 표시된다.

### FR-GIT-07 — push 이벤트 발행
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 저장소 구성(webhooks)
- **서술**: ref 갱신이 확정되면 이벤트를 발행한다. 갱신 실패 시 발행하지 않는다.
- **수용 기준**: 성공·실패 각각에서 이벤트 발행 여부가 기대와 일치.

## 코드 열람 — FR-CODE

### FR-CODE-01 — 파일 트리와 파일 내용
- **상태**: 초안 · **Tier**: T1 · **호환**: L2
- **출처**: 헌장 범위 T1, 단계 2
- **서술**: 임의의 ref·경로에서 디렉터리 목록과 파일 내용을 조회한다.
  바이너리 파일은 렌더링하지 않고 그 사실을 알린다.
- **수용 기준**: 대형 저장소에서 NFR-PERF-02를 만족하며 조회된다.

### FR-CODE-02 — 브랜치·태그 목록
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 브랜치와 태그를 조회하고 전환할 수 있다.
- **수용 기준**: 공식 API 클라이언트로 목록 조회가 성공.

### FR-CODE-03 — 커밋 이력
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: ref 또는 경로 기준으로 커밋 이력을 페이지 단위로 조회한다.
- **수용 기준**: 페이지네이션이 공식 클라이언트의 방식으로 동작.

### FR-CODE-04 — diff 조회
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 두 ref 사이 또는 단일 커밋의 변경 내용을 조회한다.
  과대 규모의 diff는 잘라내고 그 사실을 명시한다.
- **수용 기준**: NFR-PERF-03을 만족하고, 잘라내기 시 클라이언트가 이를 인지할 수 있다.

### FR-CODE-05 — 마크다운 렌더링
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: ADR-0002 (마크다운 방언 L1)
- **서술**: README 등 마크다운을 GitHub의 방언과 동일하게 렌더링한다.
- **수용 기준**: 방언 특유 문법(표, 작업 목록, 자동 링크 등)의 렌더링 결과가
  기대와 일치하고, NFR-SEC-04를 만족한다.

## 이슈 — FR-ISSUE

### FR-ISSUE-02 — 코멘트
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 이슈에 코멘트를 추가·수정·삭제한다.
- **수용 기준**: 공식 API 클라이언트로 성공하고, 수정 이력이 보존된다.

### FR-ISSUE-03 — 라벨·담당자·마일스톤
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1

### FR-ISSUE-04 — 목록 필터링
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 상태·라벨·담당자·작성자 기준으로 이슈를 필터링하고 정렬한다.
- **수용 기준**: 공식 CLI의 필터 옵션이 기대대로 동작.

### FR-ISSUE-05 — 번호 체계
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: ADR-0002
- **서술**: 이슈와 PR이 저장소 내에서 하나의 번호 공간을 공유하며,
  번호는 재사용되지 않는다.
- **수용 기준**: 이슈와 PR을 번갈아 생성했을 때 번호가 연속하며 중복되지 않는다.
- **비고**: 이 동작은 GitHub의 관측 가능한 특성이므로 재현 대상이다.

- **출처**: 헌장 범위 T1
- **서술**: 특정 파일의 특정 줄에 코멘트를 달고, 승인·변경 요청을 포함한
  리뷰를 제출한다. 코드가 바뀌어도 코멘트의 위치가 합리적으로 유지된다.
- **수용 기준**: 공식 API 클라이언트로 줄 단위 코멘트 생성·조회가 성공.
  이후 커밋으로 해당 줄이 이동했을 때의 동작이 정의되어 있고 그대로 동작한다.

### FR-PR-04 — 머지
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: PR을 머지한다. GitHub이 제공하는 머지 방식들을 지원한다.
- **수용 기준**: 각 방식의 머지 결과 커밋 그래프가 기대와 일치하고,
  표준 git 클라이언트로 확인된다.

### FR-PR-05 — 충돌 판정
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: 머지 가능 여부를 판정해 표시하고, 불가능하면 사유를 알린다.
- **수용 기준**: 충돌 있는·없는 경우 각각의 판정이 정확하며,
  판정이 비동기라면 진행 중 상태를 클라이언트가 구분할 수 있다.

### FR-PR-06 — 상태 반영
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: 헌장 범위 T1
- **서술**: PR의 열림·머지됨·닫힘 상태와 머지 커밋을 기록한다.
- **수용 기준**: 상태 전이가 API에 정확히 반영된다.

## REST API — FR-API

### FR-API-01 — 와이어 호환
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: ADR-0002
- **서술**: T1 도메인에 해당하는 REST 엔드포인트의 경로, 메서드, 요청·응답 구조가
  GitHub과 호환된다. 기존 클라이언트가 수정 없이 동작한다.
- **수용 기준**: 공식 API 클라이언트 라이브러리와 공식 CLI를 호스트 지정만 바꿔
  실행했을 때 T1 작업이 성공한다 (NFR-COMPAT-02).

### FR-API-02 — 인증 방식
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: ADR-0002, FR-AUTH-03
- **서술**: 기존 클라이언트가 사용하는 인증 헤더 형식을 그대로 받아들인다.
- **수용 기준**: 공식 클라이언트가 별도 설정 없이 인증에 성공.

### FR-API-03 — 페이지네이션
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: ADR-0002
- **서술**: 목록 응답의 페이지 이동 방식이 GitHub과 호환되어,
  기존 클라이언트의 자동 페이징이 동작한다.
- **수용 기준**: 공식 클라이언트의 페이징 기능으로 전체 목록을 누락 없이 수집.

### FR-API-04 — 오류 응답
- **상태**: 초안 · **Tier**: T1 · **호환**: L1
- **출처**: ADR-0002
- **서술**: 상태 코드와 오류 본문 구조가 호환되어, 기존 클라이언트의
  오류 처리 분기가 동작한다.
- **수용 기준**: 대표 오류 상황에서 공식 클라이언트가 오류를 정확히 분류.

### FR-API-05 — 요청 제한
- **상태**: 초안 · **Tier**: T1 · **호환**: L2
- **출처**: ADR-0002, NFR-OPS-06
- **서술**: 요청 제한을 적용하고 남은 한도를 응답에 알린다. 제한값은
  인스턴스 설정이며 GitHub.com의 값을 따르지 않는다.
- **수용 기준**: 한도 정보 전달 형식이 기존 클라이언트에 해석되고,
  관리자가 값을 조정할 수 있다.
