# 비기능 요구사항 (NFR)

작성 규칙과 상태 정의는 [README](README.md)를 따른다.

수치에 `잠정`이 붙은 항목은 실측 전 목표값이다. 단계 1에서 측정한 뒤 확정한다.
잠정 수치를 근거로 설계를 되돌릴 수 없게 만드는 결정을 내리지 않는다.

---

## 경량성 — NFR-LIGHT

헌장의 "기능이 많아도 무겁지 않을 것" 요구를 측정 가능한 형태로 옮긴 것이다.

### NFR-LIGHT-01 — 유휴 메모리 상한
- **상태**: 초안 (수치 잠정) · **Tier**: T1
- **출처**: 헌장 비기능 요구(경량성), ADR-0001
- **서술**: 사용자 20명·저장소 100개 규모 설치에서, 요청이 없는 유휴 상태의
  전체 상주 메모리(RSS 합계)가 512MB를 넘지 않는다.
- **수용 기준**: 기준 데이터셋을 적재한 인스턴스를 10분간 무부하로 두고
  RSS를 측정. 릴리스마다 자동 측정하고 이전 릴리스 대비 10% 이상 증가 시 실패.

### NFR-LIGHT-02 — 최소 사양
- **상태**: 초안 (수치 잠정) · **Tier**: T1
- **출처**: 헌장 아키텍처 제약(단일 노드 우선)
- **서술**: 2 vCPU / 4GB RAM / 20GB 디스크 단일 노드에서 T1 기능 전부가 동작한다.
- **수용 기준**: 해당 사양 VM에서 전체 수용 시험을 통과한다.

### NFR-LIGHT-03 — 배포 산출물 크기
- **상태**: 초안 (수치 잠정) · **Tier**: T2
- **출처**: 헌장 아키텍처 제약(에어갭 설치)
- **서술**: 코어 서버 바이너리가 100MB를 넘지 않는다.
- **수용 기준**: 릴리스 빌드 산출물 크기를 자동 측정. 초과 시 릴리스 차단.

### NFR-LIGHT-04 — 콜드 스타트
- **상태**: 초안 (수치 잠정) · **Tier**: T1
- **출처**: 헌장 비기능 요구(경량성)
- **서술**: 프로세스 시작부터 요청 수락까지 5초를 넘지 않는다.
- **수용 기준**: 시작 후 헬스체크가 정상 응답할 때까지의 시간을 자동 측정.

### NFR-LIGHT-05 — 기능 증가에 대한 비례성 차단
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 비기능 요구(경량성), ADR-0001
- **서술**: 활성화하지 않은 하위 시스템(패키지 레지스트리, 검색 색인, CI 등)은
  메모리·디스크·스레드를 점유하지 않는다.
- **수용 기준**: 각 하위 시스템을 끈 구성과 켠 구성의 유휴 RSS 차이를 측정해
  끈 구성에서 해당 시스템의 점유가 0임을 확인.

### NFR-LIGHT-06 — 컴파일 타임 기능 분리
- **상태**: 초안 · **Tier**: T2
- **출처**: ADR-0001
- **서술**: 선택적 기능을 빌드에서 제외할 수 있으며, 제외 시 산출물 크기가 줄어든다.
- **수용 기준**: 최소 구성 빌드와 전체 구성 빌드가 모두 성공하고,
  최소 구성의 바이너리가 더 작음을 확인.

## 이식성 — NFR-PORT

### NFR-PORT-01 — 보장 아키텍처
- **상태**: 확정 · **Tier**: T1
- **출처**: ADR-0001 (지원 등급 정책)
- **서술**: `x86_64-unknown-linux-gnu`와 `aarch64-unknown-linux-gnu`에서
  전체 기능이 동작한다.
- **수용 기준**: 두 아키텍처 각각에서 **네이티브 실행** 전체 시험 통과.
  크로스 빌드 성공만으로는 통과로 보지 않는다. 회귀 시 릴리스 차단.

### NFR-PORT-02 — 최선 노력 아키텍처
- **상태**: 확정 · **Tier**: T2
- **출처**: ADR-0001
- **서술**: 위 둘의 musl 정적 링크 변형에서 동작한다.
- **수용 기준**: 빌드 성공 + 스모크 시험 통과. 실패는 결함으로 기록하되
  릴리스를 막지 않는다.

### NFR-PORT-03 — 커뮤니티 아키텍처
- **상태**: 확정 · **Tier**: T3
- **출처**: ADR-0001
- **서술**: armv7, riscv64gc, ppc64le, s390x, loongarch64에서 빌드된다.
- **수용 기준**: 크로스 컴파일 빌드 성공 확인까지만. 동작을 보증하지 않으며,
  보증하지 않는다는 사실을 배포 문서에 명시한다.

### NFR-PORT-04 — 의존성의 이식성 제약 관리
- **상태**: 초안 · **Tier**: T1
- **출처**: ADR-0001 (의존성 선택 규칙)
- **서술**: C 라이브러리 링크 또는 아키텍처별 어셈블리를 포함하는 의존성을
  도입할 때, 보장 등급 두 아키텍처에서 빌드됨을 확인하고 기록한다.
- **수용 기준**: 의존성 추가 시 두 아키텍처 빌드가 CI에서 통과.
  시스템 라이브러리 사전 설치를 요구하는 의존성은 NFR-OPS-01 위반으로 처리.

### NFR-PORT-05 — 배포판 독립성
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 비기능 요구(이식성)
- **서술**: 특정 리눅스 배포판의 패키지·초기화 시스템에 종속되지 않는다.
- **수용 기준**: 최소 2개 계열(데비안 계열, RHEL 계열) 배포판에서 설치 시험 통과.

## 설치·운영 — NFR-OPS

### NFR-OPS-01 — 에어갭 설치
- **상태**: 확정 · **Tier**: T1
- **출처**: 헌장 아키텍처 제약(에어갭 설치)
- **서술**: 외부 네트워크가 차단된 환경에서 설치와 업그레이드가 완료된다.
  설치 중에도 런타임에도 외부 호스트로 나가지 않는다.
- **수용 기준**: 아웃바운드가 전면 차단된 네트워크에서 설치 시험 수행.
  시험 중 발생한 모든 외부 연결 시도를 실패로 판정한다.

### NFR-OPS-02 — 설치 소요 시간
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 성공의 정의 1
- **서술**: 문서만 보고 1시간 이내에 동작하는 인스턴스를 세울 수 있다.
- **수용 기준**: 프로젝트에 관여하지 않은 사람이 문서만으로 설치를 완료하는
  시험을 수행하고 소요 시간을 기록한다. 자동화할 수 없으므로 릴리스 전 수동 수행.

### NFR-OPS-03 — 외부 관리형 서비스 비의존
- **상태**: 확정 · **Tier**: T1
- **출처**: 헌장 아키텍처 제약(외부 의존성 없음)
- **서술**: 어떤 관리형 클라우드 서비스도 필수 의존성이 아니다.
  객체 저장소·데이터베이스·인증·메일을 외부로 둘 수 있으나 선택 사항이다.
- **수용 기준**: 외부 서비스 연동을 모두 끈 구성에서 전체 수용 시험 통과.

### NFR-OPS-04 — 백업·복구
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 아키텍처 제약(백업·복구)
- **서술**: 전체 상태(메타데이터, git 저장소, 첨부물)를 정합성 있는 시점으로
  백업하고, 다른 호스트에서 복구할 수 있다.
- **수용 기준**: 부하가 걸린 상태에서 백업 → 새 호스트에 복구 → 데이터 일치 검증.
  복구된 인스턴스가 전체 수용 시험을 통과해야 한다.

### NFR-OPS-05 — 업그레이드 경로
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 아키텍처 제약(업그레이드 경로)
- **서술**: 관리자가 중간 버전을 건너뛰고 업그레이드할 수 있다.
  스키마 마이그레이션은 되돌릴 수 있다.
- **수용 기준**: 최소 3개 버전을 건너뛴 업그레이드 시험과 롤백 시험 통과.

### NFR-OPS-06 — 자원 상한 강제
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 아키텍처 제약(자원 한계 존중)
- **서술**: 관리자가 정한 디스크·메모리 상한을 시스템이 강제하며,
  로그·아티팩트·캐시는 보존 정책에 따라 회수된다.
- **수용 기준**: 상한을 낮게 설정한 인스턴스에 부하를 걸어, 상한 초과 없이
  회수가 동작하고 서비스가 중단되지 않음을 확인.

### NFR-OPS-07 — 구성 요소 수 억제
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 아키텍처 제약(운영 부담 최소화)
- **서술**: 기본 배포 구성에서 관리자가 인지해야 하는 프로세스와 포트의 수를
  최소로 유지한다. 구성 요소 추가는 ADR로 근거를 남긴다.
- **수용 기준**: 기본 배포의 프로세스·포트 목록을 문서화하고, 증가 시
  근거 ADR 링크가 있는지 검토에서 확인.

## 가용성 — NFR-AVAIL

### NFR-AVAIL-01 — 계획된 중단 중 무손실
- **상태**: 초안 · **Tier**: T1
- **출처**: 헌장 비기능 요구(가용성)
- **서술**: 계획된 재시작·업그레이드 과정에서 확정된 데이터가 유실되지 않는다.
- **수용 기준**: 쓰기 부하 중 재시작을 반복하며 확정 응답을 받은 모든 작업이
  재시작 후 조회되는지 확인.

### NFR-AVAIL-02 — 비정상 종료 복구
- **상태**: 초안 · **Tier**: T1
- **출처**: 헌장 비기능 요구(내구성)
- **서술**: 프로세스 강제 종료나 전원 차단 후 재시작 시 자동으로 정합성을
  회복하며, 수동 개입을 요구하지 않는다.
- **수용 기준**: 쓰기 중 강제 종료를 반복 주입하고, 재시작 후 정합성 검사 통과.

## 성능 — NFR-PERF

기준 저장소 규모는 단계 1에서 확정한다. 아래 `대형`은 잠정으로
"커밋 10만 개 이상, 작업 트리 1GB 이상"을 뜻한다.

### NFR-PERF-01 — clone 처리량
- **상태**: 보류 (기준 미확정) · **Tier**: T1
- **출처**: 헌장 비기능 요구(성능)
- **서술**: 대형 저장소의 전체 clone이 동일 하드웨어에서 순수 git 서버 대비
  현저히 느리지 않다.
- **수용 기준**: 기준 저장소로 clone 시간을 측정해 기준선 대비 배수로 관리.
  허용 배수는 단계 1 실측 후 확정.

### NFR-PERF-02 — 코드 열람 응답
- **상태**: 초안 (수치 잠정) · **Tier**: T1
- **출처**: 헌장 비기능 요구(성능)
- **서술**: 파일 트리·파일 내용·커밋 목록 조회가 대형 저장소에서도
  p95 500ms 이내에 응답한다.
- **수용 기준**: 기준 저장소에 대해 부하 시험으로 p95 측정.

### NFR-PERF-03 — diff 생성
- **상태**: 초안 (수치 잠정) · **Tier**: T1
- **출처**: 헌장 비기능 요구(성능)
- **서술**: 변경 파일 1000개 규모의 diff가 p95 3초 이내에 응답한다.
  초과 규모에서는 잘라내고 그 사실을 명시한다.
- **수용 기준**: 대형 diff 픽스처로 응답 시간과 잘라내기 동작을 확인.

### NFR-PERF-04 — 성능 회귀 감시
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 비기능 요구(성능)
- **서술**: 위 지표를 릴리스마다 측정해 회귀를 검출한다.
- **수용 기준**: 성능 시험이 CI에 포함되고, 기준선 대비 악화 시 경고를 발생.

## 확장성 — NFR-SCALE

### NFR-SCALE-01 — 명시적 한계 공개
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 비기능 요구(확장성)
- **서술**: 사용자 수, 저장소 수, 동시 CI 작업 수의 검증된 상한을 문서에 공개한다.
  검증하지 않은 규모를 지원한다고 주장하지 않는다.
- **수용 기준**: 공개된 각 상한에 대해 실제 부하 시험 결과가 존재.

### NFR-SCALE-02 — 수평 확장 가능성
- **상태**: 보류 (아키텍처 미확정) · **Tier**: T3
- **출처**: 헌장 아키텍처 제약(단일 노드 우선)
- **서술**: 단일 노드가 한계에 도달하면 구성 요소를 분리해 확장할 수 있다.
  단일 노드 배포가 기본값이라는 점은 유지한다.
- **수용 기준**: 분리 배포 구성에서 전체 수용 시험 통과.

## 내구성 — NFR-DURA

### NFR-DURA-01 — push 확정성
- **상태**: 초안 · **Tier**: T1
- **출처**: 헌장 비기능 요구(내구성)
- **서술**: 클라이언트에 성공을 응답한 push는 유실되지 않는다.
  응답 전에 객체와 ref 갱신이 영속화되어야 한다.
- **수용 기준**: push 응답 직후 전원 차단을 주입하고, 재시작 후 해당 ref와
  객체가 존재하는지 확인.

### NFR-DURA-02 — 메타데이터와 git 객체의 정합성
- **상태**: 초안 · **Tier**: T1
- **출처**: 헌장 아키텍처 제약(백업·복구)
- **서술**: 메타데이터 저장소와 git 저장소가 서로 어긋난 상태로 남지 않는다.
  어긋남이 발생하면 탐지하고 보고한다.
- **수용 기준**: 정합성 검사 도구를 제공하고, 장애 주입 시험 후 검사를 통과.

## 보안 — NFR-SEC

### NFR-SEC-01 — CI 작업 격리
- **상태**: 보류 (격리 방식 미결) · **Tier**: T2
- **출처**: 헌장 위험(CI 격리)
- **서술**: 워크플로가 실행하는 임의 코드가 호스트, 다른 작업, 다른 저장소의
  데이터에 접근할 수 없다.
- **수용 기준**: 탈출 시도 시나리오 모음을 작성해 모두 차단됨을 확인.
  위협 모델 문서가 단계 4 이전에 존재해야 한다.

### NFR-SEC-02 — 시크릿 취급
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 비기능 요구(보안)
- **서술**: 시크릿은 저장 시 암호화되고, 로그·오류 메시지·API 응답에 나타나지 않으며,
  신뢰할 수 없는 출처(포크에서 온 PR)의 실행에 주입되지 않는다.
- **수용 기준**: 시크릿 값이 로그 전체에서 검출되지 않음을 자동 확인.
  포크 PR 시나리오에서 미주입을 확인.

### NFR-SEC-03 — 웹훅 SSRF 방어
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 비기능 요구(보안)
- **서술**: 사용자가 지정한 웹훅 대상으로의 요청이 내부망·루프백·링크로컬
  주소에 도달하지 않는다. 관리자가 허용 목록으로 예외를 둘 수 있다.
- **수용 기준**: 내부 주소 및 리다이렉트를 통한 우회 시도가 차단됨을 확인.

### NFR-SEC-04 — 사용자 입력 렌더링
- **상태**: 초안 · **Tier**: T1
- **출처**: 헌장 비기능 요구(보안)
- **서술**: 마크다운·파일 내용·저장소 이름 등 사용자 입력이 스크립트 실행으로
  이어지지 않는다.
- **수용 기준**: XSS 페이로드 모음에 대해 렌더링 결과가 안전함을 자동 확인.

### NFR-SEC-05 — 권한 판정의 단일 지점화
- **상태**: 초안 · **Tier**: T1
- **출처**: 헌장 아키텍처 제약, ADR-0002(권한 역할 이름 L2 호환)
- **서술**: 저장소 공개 범위·협업자 역할·팀 권한이 겹치는 판정을 한 곳에서
  수행한다. 호출 지점마다 판정을 재구현하지 않는다.
- **수용 기준**: 권한 조합 전수 시험이 단일 판정 모듈에 대해 존재하고,
  API·git 서버·웹이 모두 그 모듈을 경유함을 검토에서 확인.

### NFR-SEC-06 — 감사 로그
- **상태**: 초안 · **Tier**: T2
- **출처**: 헌장 배경(감사 추적 자체 통제)
- **서술**: 권한 변경, 인증, 저장소 생성·삭제, 관리자 작업이 변조하기 어려운
  형태로 기록된다.
- **수용 기준**: 대상 작업 목록에 대해 각각 감사 항목이 생성됨을 확인.

## 호환성 — NFR-COMPAT

### NFR-COMPAT-01 — 적합성 시험의 릴리스 차단력
- **상태**: 확정 · **Tier**: T1
- **출처**: ADR-0002
- **서술**: L1 등급 대상에 대한 적합성 시험이 CI에 포함되며,
  통과하지 못하면 릴리스하지 않는다.
- **수용 기준**: 적합성 시험 작업이 릴리스 파이프라인의 차단 조건으로 설정됨.

### NFR-COMPAT-02 — 판정 주체의 외부성
- **상태**: 확정 · **Tier**: T1
- **출처**: ADR-0002
- **서술**: 호환 여부는 자체 구현한 클라이언트가 아니라 **기존 GitHub 클라이언트**로
  판정한다. 표준 git 클라이언트, 공식 CLI, 공식 API 클라이언트 라이브러리를 사용한다.
- **수용 기준**: 적합성 시험이 위 외부 도구를 실제로 실행함을 확인.

### NFR-COMPAT-03 — 호환율 측정과 공개
- **상태**: 초안 · **Tier**: T2
- **출처**: ADR-0002 (움직이는 표적 위험)
- **서술**: L1 대상 표면 중 몇 %가 호환되는지 측정해 공개한다.
- **수용 기준**: 대상 표면 목록과 통과 항목 수가 릴리스마다 산출·게시됨.
  측정 없는 호환 주장을 문서에 쓰지 않는다.

### NFR-COMPAT-04 — 기준 버전과 추종 주기
- **상태**: 보류 (미결) · **Tier**: T2
- **출처**: ADR-0002 미결 사항
- **서술**: 호환 기준으로 삼는 상류 API 버전과 변경 추종 주기를 정하고 공개한다.
- **수용 기준**: 기준 버전이 문서에 명시되고, 추종 검토가 정기적으로 수행됨.

### NFR-COMPAT-05 — 에어갭에서의 워크플로 호환
- **상태**: 보류 (해소안 미결) · **Tier**: T2
- **출처**: ADR-0002 충돌 1, 헌장 최우선 위험
- **서술**: 외부 액션을 참조하는 실제 워크플로 파일이 **네트워크가 차단된
  인스턴스에서** 수정 없이 실행된다.
- **수용 기준**: 아웃바운드 차단 환경에서 외부 액션 참조를 포함한 워크플로를
  실행해 성공. **문법 파싱 성공은 통과로 보지 않는다.**
- **비고**: 이 요구사항은 NFR-OPS-01과 정면으로 충돌하며, 액션 미러링 계층 없이는
  달성 불가능하다. 해소안이 ADR로 확정되기 전까지 `보류`를 유지한다.

## 추가 — T2·T3 전개에서 도출됨

아래는 [fr-tier2.md](fr-tier2.md), [fr-tier3.md](fr-tier3.md)를 전개하면서
드러난 비기능 요구다. 공통점은 **에어갭 제약이 기능 도메인마다 같은 모양으로
재등장한다**는 것이다.

### NFR-OPS-08 — 외부 산출물 반입 절차의 단일화
- **상태**: 초안 · **Tier**: T2
- **출처**: NFR-OPS-01, FR-CI-05, FR-PKG-03, FR-SCAN-02, FR-EXT-03
- **서술**: 폐쇄망 인스턴스가 필요로 하는 외부 산출물(재사용 액션, 패키지,
  취약점 데이터, 확장)의 반입을 **하나의 일관된 절차**로 제공한다.
  기능마다 다른 반입 방식을 만들지 않는다.
- **수용 기준**: 네 종류 산출물이 동일한 절차와 도구로 반입되며,
  절차 문서가 하나다.
- **비고**: 이 요구를 초기에 세우지 않으면 도메인마다 제각각의 반입 방식이 생기고,
  관리자가 감당해야 할 운영 지식이 네 배가 된다. NFR-OPS-07 위반으로 이어진다.

### NFR-SEC-07 — 오프라인 보안 데이터의 신선도 표시
- **상태**: 초안 · **Tier**: T3
- **출처**: FR-SCAN-02, NFR-OPS-01
- **서술**: 외부에서 반입한 보안 데이터에 기준 시점을 기록하고,
  그 데이터에 근거한 모든 판정 결과에 함께 표시한다.
  데이터가 오래되면 경고한다.
- **수용 기준**: 스캔 결과 화면과 API 응답에 데이터 기준 시점이 포함되고,
  임계 기간을 넘기면 경고가 표시된다.
- **비고**: 폐쇄망에서 갱신이 늦으면 "취약점 없음"이 사실상 거짓이 된다.
  신선도를 감추는 것은 결함이 아니라 위험이다.

### NFR-SEC-08 — 사용자 콘텐츠의 출처 격리
- **상태**: 초안 · **Tier**: T3
- **출처**: FR-PAGES-02, NFR-SEC-04
- **서술**: 사용자가 제공한 콘텐츠를 그대로 제공하는 기능(정적 사이트 호스팅,
  첨부물 다운로드 등)은 본체 애플리케이션과 다른 출처에서 서비스한다.
- **수용 기준**: 사용자 콘텐츠에서 실행된 스크립트가 본체의 세션·토큰에
  접근할 수 없음을 확인.
- **비고**: 같은 출처에서 제공하면 사용자 콘텐츠가 곧 전역 XSS 경로가 된다.

### NFR-SEC-09 — 인증 잠금 방지
- **상태**: 초안 · **Tier**: T3
- **출처**: FR-SSO-03
- **서술**: 외부 인증 연동의 오설정이나 신원 공급자 장애가 인스턴스에 대한
  관리 접근의 영구 상실로 이어지지 않는다.
- **수용 기준**: 신원 공급자를 중단시킨 상태에서 관리자가 접근해
  설정을 되돌릴 수 있다.

### NFR-COMPAT-06 — 생태계별 클라이언트 적합성
- **상태**: 초안 · **Tier**: T3
- **출처**: FR-PKG-01, NFR-COMPAT-02
- **서술**: 패키지 레지스트리처럼 생태계마다 프로토콜이 다른 영역은,
  지원한다고 선언한 생태계 각각에 대해 **해당 생태계의 공식 클라이언트로**
  적합성 시험을 수행한다.
- **수용 기준**: 지원 선언과 적합성 시험 존재가 일대일로 대응한다.
  시험 없는 생태계를 지원 목록에 넣지 않는다.
