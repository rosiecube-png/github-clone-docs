# 미결 질문 — 인터뷰 백로그

요구사항 도출은 장기전이다. 이 문서는 그 인터뷰가 흩어지지 않게 하는 장치다.

각 질문은 **무엇을 막고 있는지**를 함께 기록한다. 막는 것이 없는 질문은
지금 물을 필요가 없다. 답이 나오면 ADR로 옮기고 여기서는 `해소`로 표시한다.

## 규칙

- 질문 하나가 여러 요구사항을 막을 수 있다. 많이 막는 것부터 묻는다.
- 답이 없어도 진행할 수 있는 작업은 먼저 한다. 질문이 전체를 멈추게 두지 않는다.
- 답을 추측으로 채우지 않는다. 추측이 필요하면 그렇게 표시하고,
  그 위에 되돌릴 수 없는 결정을 쌓지 않는다.
- 해소된 질문은 지우지 않는다. 왜 그렇게 정했는지가 나중에 필요하다.

## 상태

| 상태 | 뜻 |
| --- | --- |
| `대기` | 아직 묻지 않음 |
| `질의중` | 물었고 답을 기다리는 중 |
| `해소` | 답이 ADR로 기록됨 |

## 우선순위 1 — 단계 0을 막고 있는 것

단계 0의 관문은 「배정된 가정 8개가 `검증됨` 또는 `반증됨`이 된다」이다.
아래 질문들이 그 관문에 직접 걸려 있다.

### Q-01 — 재사용 액션을 폐쇄망에서 어떻게 해석할 것인가
- **상태**: 대기
- **막고 있는 것**: FR-CI-05, FR-CI-13, FR-CI-14, FR-CI-17, NFR-COMPAT-05,
  NFR-OPS-08, ASM-10, CON-05
- **배경**: 워크플로 문법을 호환하면 워크플로는 외부 액션을 참조한다.
  그 해석이 외부로 나가면 CON-01을 위반한다.
  **문법 호환은 워크플로 호환이 아니다.**
- **필요한 답**: 미러링 계층을 둘 것인가, 핵심 액션을 내장 구현할 것인가, 둘 다인가.
  반입 절차를 관리자에게 얼마나 맡길 것인가.

### Q-02 — 웹 프런트엔드를 어떤 방식으로 만들 것인가
- **상태**: 대기
- **막고 있는 것**: `github-clone-web` 착수 전체, ASM-09, FR-PR-03, FR-CODE-04,
  FR-WEB-01, NFR-A11Y-05, NFR-LIGHT-03
- **배경**: Rust/WASM인가, 서버사이드 렌더링에 최소 JavaScript인가.
  경량성에는 후자가 유리하나 대형 diff의 줄 단위 코멘트 앵커링을 감당하는지 미확인.
- **비고**: 인터뷰가 아니라 **실험으로 답할 질문**이다.
  diff 뷰어 프로토타입으로 양쪽을 실측 비교한다.

### Q-03 — CI 작업을 무엇으로 격리할 것인가
- **상태**: 대기
- **막고 있는 것**: FR-CI-12, FR-CI-17, NFR-SEC-01
- **배경**: 임의 사용자 코드를 실행하므로 격리 실패는 곧 서버 장악이다.
  컨테이너 런타임에 의존하면 아키텍처별 이미지 문제가 NFR-PORT와 얽힌다.
- **필요한 답**: 컨테이너 런타임을 필수 의존성으로 둘 것인가.
  둔다면 NFR-OPS-03(외부 의존성 없음)의 예외로 인정할 것인가.

### Q-04 — 데이터베이스를 내장으로 갈 것인가 외부로 둘 것인가
- **상태**: 대기
- **막고 있는 것**: `github-clone-api` 착수, NFR-LIGHT-01·02, NFR-OPS-03,
  NFR-SCALE-02, NFR-DR-02, CON-09
- **배경**: 내장은 단일 노드·경량·에어갭에 유리하고, 외부는 확장과 운영 생태계에 유리하다.
  헌장은 단일 노드를 우선하지만 고가용성(NFR-DR-02)과 상충한다.

## 우선순위 2 — 목표 수치가 없어 요구사항이 `보류`인 것

이 질문들의 공통점은 **우리가 정할 값이 아니라는 것**이다.
대상 조직의 요구에서 나와야 한다.

### Q-05 — 복구 목표(RTO·RPO)를 얼마로 할 것인가
- **상태**: 대기
- **막고 있는 것**: NFR-DR-01(`보류`), NFR-DR-04
- **배경**: 엔터프라이즈가 이전을 결재하려면 이 숫자가 필요하다.
  **측정하지 않은 목표를 공개하지 않는다**는 원칙 때문에 값 없이는 진행할 수 없다.

### Q-06 — 성능 기준 저장소의 규모
- **상태**: 대기
- **막고 있는 것**: NFR-PERF-01(`보류`), NFR-PERF-02·03, NFR-SWITCH-01, ASM-02
- **배경**: 「대형 저장소」를 정의하지 않으면 성능 요구를 측정할 수 없다.
  현재 잠정값은 커밋 10만 개·작업 트리 1GB.

### Q-07 — 인스턴스 규모의 목표 상한
- **상태**: 대기
- **막고 있는 것**: NFR-SCALE-01, NFR-SCALE-03, NFR-LIGHT-01, NFR-SWITCH-03, ASM-01
- **배경**: 사용자 20명 규모를 잠정 기준으로 썼다. 목표가 200명이면
  경량성 수치 전체를 다시 잡아야 한다.

### Q-08 — 성능 동등성의 허용 배수
- **상태**: 대기
- **막고 있는 것**: NFR-SWITCH-01(`보류`)
- **배경**: 사용자는 절대값이 아니라 기존 환경과의 비교로 판단한다.
  「현저히 나쁘지 않다」를 숫자로 바꿔야 한다.

### Q-09 — 접근성은 어느 표준의 어느 등급을 목표로 하는가
- **상태**: 대기
- **막고 있는 것**: NFR-A11Y-04(`보류`)
- **배경**: 공공·금융 조달에서는 이것이 기능 평가 이전의 필수 조건이 된다.

## 우선순위 3 — 나중에 정해도 되는 것

### Q-10 — 호환 기준 상류 버전과 추종 주기
- **상태**: 대기
- **막고 있는 것**: NFR-COMPAT-04(`보류`), NFR-COMPAT-03의 분모 정의

### Q-11 — 패키지 레지스트리의 지원 생태계와 우선순위
- **상태**: 대기
- **막고 있는 것**: FR-PKG-01, FR-PKG-06, NFR-COMPAT-06
- **배경**: 생태계마다 프로토콜이 완전히 다르다. 하나를 구현했다고 나머지가 따라오지 않는다.

### Q-12 — GraphQL 형태 호환(L2)의 구체적 경계
- **상태**: 대기
- **막고 있는 것**: FR-GQL-01·02·06

### Q-13 — git 객체의 저장 구조
- **상태**: 대기
- **막고 있는 것**: FR-FORK-06(`보류`), NFR-LIGHT-02의 디스크 산정
- **배경**: 포크 간 객체 공유는 디스크를 크게 아끼지만 격리와 상충한다.
  요구사항에는 격리 우선으로 적어 두었다.

### Q-14 — 지원 리눅스 배포판
- **상태**: 대기
- **막고 있는 것**: NFR-PORT-05, FR-INSTALL-03

### Q-15 — 라이선스 모델
- **상태**: 대기
- **막고 있는 것**: FR-ADMIN-10(`보류`), NFR-LIFECYCLE-07의 고지 범위,
  간접적으로 Q-01의 액션 재배포 검토

## 우리가 조사해서 답할 것 (인터뷰 대상 아님)

사용자에게 물을 질문이 아니라, 우리가 확인해서 ADR로 기록할 항목이다.
전부 미검증 가정과 짝을 이룬다.

| 항목 | 검증할 가정 | 관련 요구사항 |
| --- | --- | --- |
| 의존성 후보가 보장 등급 두 아키텍처에서 크로스 빌드되는가 | ASM-08 | NFR-PORT-01~05 |
| `git` 실행 파일 래핑이 성능·동시성·권한 삽입을 감당하는가 | ASM-07 | FR-GIT-01~09 |
| 공식 CLI가 호스트 지정만으로 붙는가 | ASM-11 | FR-API-01~05, FR-CLI-02 |
| 이슈·PR 번호 공간 공유가 관측 가능한 동작인가 | ASM-12 | FR-ISSUE-05, FR-MIG-03 |
| 대형 diff 렌더링의 프런트엔드 방식별 실측 | ASM-09 | Q-02 |
| 재사용 액션들의 재배포 라이선스 | ASM-10 | Q-01, CON-05 |
| **폐쇄망 고객에게 보안 패치를 전달할 경로가 실재하는가** | ASM-16 | NFR-LIFECYCLE-01 |
| **상류 API만으로 양방향 동기화가 가능한가** | ASM-17 | FR-MIG-08·09, NFR-SWITCH-02·04 |
| 담당 저장소 매핑이 실제 구현 경계와 일치하는가 | ASM-13 | 저장소 구성 8개 |
| 폐쇄망·데이터 주권 수요가 실재하는가 | ASM-14 | **제품 전제 전체** |
| 기존 상용 제품과의 차별점이 성립하는가 | ASM-15 | 헌장 배경 |

마지막 두 항목은 다른 어떤 검증보다 우선한다. 이것들이 무너지면
요구사항 몇 개가 아니라 프로젝트가 무너진다.

## 선후 관계

일부 요구사항은 질문이 아니라 **다른 요구사항**에 막혀 있다.

| 막힌 것 | 선행 조건 |
| --- | --- |
| FR-SCAN-03 취약점 알림 | FR-SCAN-02 오프라인 데이터 갱신 |
| FR-SCAN-06 의존성 자동 업데이트 | FR-SCAN-02, FR-PKG-03 |
| FR-ADVISORY-03 권고 연동 | FR-SCAN-02 |
| FR-PROT-11 필수 대화 해결 | FR-PR-10 리뷰 스레드 해결 |
| FR-PROT-04 필수 상태 체크 | FR-CI-11, FR-API-06 |
| NFR-LIFECYCLE-08 제품 구성 요소 목록 | NFR-LIFECYCLE-06 재현 가능 빌드 |
| FR-SIGN-03 인스턴스 서명 정책 | FR-CODE-06 웹 편집 |
