# 기능 요구사항 — Tier 3

작성 규칙과 상태 정의는 [README](README.md)를 따른다.
Tier 1은 [fr.md](fr.md), Tier 2는 [fr-tier2.md](fr-tier2.md).

Tier 3은 "GitHub 동등성"에 해당한다. 여기까지 채워야 헌장의 성공 기준 2
(워크플로를 바꾸지 않고 계속 일할 수 있다)가 예외 없이 성립한다.

이 계층의 상당수가 **에어갭 제약과 다시 충돌한다.** 취약점 데이터베이스,
패키지 업스트림, 확장 배포가 모두 외부에서 데이터를 받아야 하는 기능이기
때문이다. 해당 항목에 명시했다.

## 패키지 레지스트리 — FR-PKG

### FR-PKG-01 — 레지스트리 프로토콜 호환
- **상태**: 초안 · **Tier**: T3 · **호환**: L1
- **출처**: 헌장 범위 T3
- **서술**: 주요 패키지 생태계의 클라이언트가 표준 도구로 게시·설치할 수 있도록
  각 생태계의 레지스트리 프로토콜을 구현한다. 지원 생태계 목록은 별도로 정한다.
- **수용 기준**: 각 생태계의 **공식 클라이언트**로 게시·설치가 성공한다.
  우리 클라이언트로 통과시킨 것은 통과가 아니다.
- **비고**: 생태계마다 프로토콜이 완전히 다르다. 하나를 구현했다고 나머지가
  따라오지 않는다. 우선순위를 정해야 한다.
  [open-questions.md](open-questions.md) Q-08.

### FR-PKG-02 — 인증과 권한 연동
- **상태**: 초안 · **Tier**: T3 · **호환**: L1
- **출처**: FR-AUTH-03, NFR-SEC-05
- **서술**: 개인 액세스 토큰으로 레지스트리에 인증하고, 패키지 접근 권한이
  소유 저장소·조직의 권한을 따른다.
- **수용 기준**: 권한 조합별 게시·설치 성공·실패가 기대와 일치.

### FR-PKG-03 — 업스트림 프록시
- **상태**: **보류** (에어갭 충돌) · **Tier**: T3 · **호환**: L3
- **출처**: NFR-OPS-01
- **서술**: 공개 레지스트리의 패키지를 인스턴스가 대신 받아 캐시하는 기능.
  폐쇄망에서는 관리자가 미리 반입한 것만 제공된다.
- **수용 기준**: 프록시를 끈 구성에서 반입된 패키지만으로 설치가 성립하고,
  런타임에 외부 호출이 발생하지 않는다.
- **비고**: 프록시는 편의 기능이며 **기본값은 꺼짐**이어야 한다.

### FR-PKG-04 — 보존 정책
- **상태**: 초안 · **Tier**: T3 · **호환**: L3
- **출처**: NFR-OPS-06
- **서술**: 버전 수·용량·기간 기준으로 오래된 패키지를 회수한다.
  회수 전 예고하고, 회수 이력을 남긴다.
- **수용 기준**: 상한 초과 시 회수가 동작하고 감사 항목이 남는다.

## 정적 사이트 호스팅 — FR-PAGES

### FR-PAGES-01 — 게시
- **상태**: 초안 · **Tier**: T3 · **호환**: L2
- **출처**: 헌장 범위 T3
- **서술**: 저장소의 지정한 브랜치·디렉터리 또는 워크플로 산출물을
  정적 사이트로 게시한다.
- **수용 기준**: 게시 후 지정 경로에서 콘텐츠가 제공된다.

### FR-PAGES-02 — 출처 격리
- **상태**: 초안 · **Tier**: T3 · **호환**: L3
- **출처**: NFR-SEC-04
- **서술**: 게시된 사이트는 사용자가 작성한 임의의 콘텐츠이므로,
  본체 애플리케이션과 **다른 출처(origin)** 에서 제공한다.
  게시 사이트의 스크립트가 본체의 세션·토큰에 접근할 수 없어야 한다.
- **수용 기준**: 게시 사이트에서 본체 자격 증명 탈취 시나리오가 차단됨을 확인.
- **비고**: 같은 출처에서 제공하면 사용자 콘텐츠가 곧 전역 XSS가 된다.
  이 항목은 편의가 아니라 보안 요구다.

### FR-PAGES-03 — 접근 제어
- **상태**: 초안 · **Tier**: T3 · **호환**: L2
- **서술**: 비공개 저장소에서 게시한 사이트는 권한 있는 사용자에게만 제공한다.
- **수용 기준**: 권한 없는 요청이 콘텐츠를 받지 못한다.

## 보안 스캐닝 — FR-SCAN

이 도메인 전체가 **외부 데이터에 의존**한다. 에어갭 제약과의 관계를
항목마다 명시한다.

### FR-SCAN-01 — 의존성 인벤토리
- **상태**: 초안 · **Tier**: T3 · **호환**: L2
- **출처**: 헌장 범위 T3
- **서술**: 저장소의 의존성 정의 파일을 해석해 사용 중인 구성 요소 목록을 만든다.
  이 단계는 외부 데이터가 필요 없다.
- **수용 기준**: 지원 생태계별 정의 파일에서 목록이 정확히 산출된다.

### FR-SCAN-02 — 취약점 데이터베이스 오프라인 갱신
- **상태**: **보류** (에어갭 충돌) · **Tier**: T3 · **호환**: L3
- **출처**: NFR-OPS-01, NFR-SEC-07
- **서술**: 취약점 데이터베이스를 관리자가 오프라인으로 반입·갱신할 수 있다.
  인스턴스가 스스로 외부에서 받아오지 않는 것이 기본값이다.
- **수용 기준**: 아웃바운드 차단 환경에서 반입한 데이터만으로 스캔이 동작하고,
  데이터의 기준 시점이 사용자에게 표시된다.
- **비고**: 폐쇄망에서 취약점 데이터가 오래되면 "취약점 없음"이 거짓이 된다.
  **데이터 신선도를 반드시 표시해야 한다.** 표시 없는 스캔 결과는 위험하다.

### FR-SCAN-03 — 취약점 알림
- **상태**: 보류 (FR-SCAN-02 선행) · **Tier**: T3 · **호환**: L2
- **서술**: 인벤토리와 데이터베이스를 대조해 영향받는 저장소에 알린다.
- **수용 기준**: 알려진 취약 버전을 담은 시험 저장소에서 탐지된다.

### FR-SCAN-04 — 코드 스캐닝 결과 수용
- **상태**: 초안 · **Tier**: T3 · **호환**: L1
- **출처**: 헌장 범위 T3
- **서술**: 정적 분석 도구가 만든 표준 형식의 결과를 받아 저장하고,
  PR과 코드 화면에 표시한다. 분석기 자체를 우리가 만들지 않는다.
- **수용 기준**: 표준 형식 결과 파일이 수정 없이 수용되고 표시된다.

### FR-SCAN-05 — 시크릿 스캐닝
- **상태**: 초안 · **Tier**: T3 · **호환**: L2
- **서술**: 커밋 내용에서 자격 증명 패턴을 탐지해 경고한다.
  push 시점 차단을 선택할 수 있다.
- **수용 기준**: 시험 패턴 모음에 대한 탐지율과 오탐률을 측정해 공개한다.

## 인증 연동 — FR-SSO

### FR-SSO-01 — 디렉터리·SSO 연동
- **상태**: 초안 · **Tier**: T3 · **호환**: L3
- **출처**: 헌장 범위 T3
- **서술**: 조직의 기존 인증 체계(디렉터리 서비스, SAML, OIDC)와 연동해
  로그인할 수 있다. 지원 방식은 인스턴스 설정으로 선택한다.
- **수용 기준**: 각 방식별로 실제 신원 공급자와의 연동 시험이 통과.

### FR-SSO-02 — 계정 자동 프로비저닝
- **상태**: 초안 · **Tier**: T3 · **호환**: L3
- **서술**: 외부 신원 체계의 사용자·그룹 정보를 받아 계정과 팀 소속을
  자동으로 생성·갱신·비활성화한다.
- **수용 기준**: 외부에서의 비활성화가 인스턴스 접근 차단으로 이어진다.

### FR-SSO-03 — 로컬 계정 병행과 잠금 방지
- **상태**: 초안 · **Tier**: T3 · **호환**: L3
- **출처**: 운영 요구
- **서술**: 외부 인증을 켜도 관리자용 로컬 계정으로 로그인할 수 있는 경로를
  유지한다. 신원 공급자 장애가 인스턴스 전면 잠금으로 이어지지 않아야 한다.
- **수용 기준**: 신원 공급자를 중단시킨 상태에서 관리자가 로그인해
  설정을 되돌릴 수 있다.
- **비고**: 이 항목이 없으면 설정 실수 한 번으로 인스턴스가 영구 잠긴다.

### FR-SSO-04 — git 접근 경로
- **상태**: 초안 · **Tier**: T3 · **호환**: L1
- **출처**: FR-GIT-03
- **서술**: 외부 인증을 쓰더라도 git 프로토콜 접근은 토큰·공개키로 계속 동작한다.
- **수용 기준**: SSO 구성에서 표준 git 클라이언트 왕복이 성공.

## 포크·미러 — FR-FORK

### FR-FORK-01 — 포크
- **상태**: 초안 · **Tier**: T3 · **호환**: L1
- **출처**: 헌장 범위 T3
- **서술**: 저장소를 다른 소유자 아래로 복제하고 원본과의 관계를 기록한다.
  원본이 비공개면 포크의 공개 범위가 넓어지지 않는다.
- **수용 기준**: 포크의 공개 범위가 원본을 넘지 않음을 확인.

### FR-FORK-02 — 포크 간 Pull Request
- **상태**: 초안 · **Tier**: T3 · **호환**: L1
- **출처**: FR-PR-01
- **서술**: 포크의 브랜치에서 원본 저장소로 PR을 생성한다.
- **수용 기준**: 공식 CLI로 교차 저장소 PR 생성이 성공.

### FR-FORK-03 — 신뢰 경계
- **상태**: 초안 · **Tier**: T3 · **호환**: L1
- **출처**: NFR-SEC-02, FR-CI-06
- **서술**: 포크에서 온 PR은 신뢰할 수 없는 출처로 취급한다.
  시크릿 미주입, 워크플로 실행 승인 요구가 적용된다.
- **수용 기준**: 포크 PR에서 시크릿이 주입되지 않고, 승인 전 실행되지 않는다.

### FR-FORK-04 — 업스트림 동기화
- **상태**: 초안 · **Tier**: T3 · **호환**: L2
- **서술**: 포크를 원본의 최신 상태로 갱신한다. 충돌 시 사유를 알린다.
- **수용 기준**: 동기화 후 포크의 ref가 원본과 일치.

### FR-FORK-05 — 저장소 미러링
- **상태**: 초안 · **Tier**: T3 · **호환**: L3
- **출처**: 헌장 범위 T3
- **서술**: 외부 git 저장소를 주기적으로 가져오거나 외부로 밀어낸다.
  폐쇄망에서는 기본으로 비활성이며 관리자가 대상을 허용해야 한다.
- **수용 기준**: 허용 목록 밖 대상으로의 연결이 차단된다.

### FR-FORK-06 — 객체 공유
- **상태**: 보류 (저장 구조 미결) · **Tier**: T3 · **호환**: L3
- **출처**: NFR-LIGHT-02, NFR-OPS-06
- **서술**: 포크 사이에 git 객체를 공유해 디스크 사용을 줄인다.
  공유가 저장소 삭제·권한 변경 시 데이터 손상이나 유출로 이어지지 않아야 한다.
- **수용 기준**: 원본 삭제 후에도 포크가 온전하고, 비공개 원본의 객체가
  포크를 통해 노출되지 않는다.
- **비고**: 디스크 절감과 격리가 정면으로 상충한다. 격리를 우선한다.

  제한한다. 위임된 권한은 사용자의 권한을 넘지 못한다.
- **수용 기준**: 권한 상승 시도가 차단됨을 확인.

### FR-EXT-03 — 확장 배포와 반입
- **상태**: **보류** (에어갭 충돌) · **Tier**: T3 · **호환**: L3
- **출처**: NFR-OPS-01
- **서술**: 확장을 찾아 설치하는 수단을 제공하되, 폐쇄망에서는 관리자가
  반입한 것만 설치 가능하다. 인스턴스가 외부 마켓에 직접 연결하지 않는 것이 기본값이다.
- **수용 기준**: 아웃바운드 차단 환경에서 반입 절차만으로 확장 설치가 완료된다.

### FR-EXT-04 — 앱 자격 증명 관리
